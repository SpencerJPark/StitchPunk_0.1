DOTS Animator Style Guide

How every tab of the Clip Editor window should look: shadcn/ui's calm, neutral control language laid over Blender's flush, dense editor layout, painted in the Unity editor's own theme colours. The rules at the bottom carry ids (R01–R22) so specs and capture audits can cite exactly what a screen breaks.

Rules

Judged against every tab capture. A screen passes only when it breaks none. The "Seen" lines are real failures from the 2026-09-15 captures.

Text

R01No clipped text, anywhere.A label fits, truncates with an ellipsis and a tooltip holding the full text, or wraps in its own container. A control is at least its line height plus 4px of vertical padding.Seen: the tab strip cuts every descender ("Rigs" reads "Rias"); Ragdoll body rows show only the top half of each name; Flipbooks' Import settings header and its row are cut.
R02Four text styles only.11 meta, 12 body, 13/600 pane title, 16/600 detail title. Hierarchy comes from weight and muted colour, not from new sizes.Seen: 9, 10 and 14px sizes in the stylesheet with no role.
R03Say it once.A value shown in a row's meta is not repeated in the row's title or the header beside it. Counts belong in a badge or the meta column.Seen: Flipbooks frame rows print "#0 64×64" beside a "0" label, 16 times.

Space and alignment

R04Spacing comes from the scale.Every margin, padding and gap is 0, 2, 4, 8, 12, 16 or 24px, set with gap on a flex container rather than per-element margins.
R05One inset per column.Headers, hints, fields and list rows in a column start 12px from its edge. Nothing indents by accident.Seen: Ragdoll's "Inspector", "Select a body." and "Rig settings" each start at a different x.
R06Headers share a row.Every column header is 32px tall with its title on the same baseline, so the three columns read as one window.Seen: Ragdoll's "Viewport" title sits 12px above "Bodies" and "Inspector".
R07Controls in a row share one height and one gap.A toolbar row is 24px controls with 4px gaps; groups separate with a 1px divider, not with extra space.Seen: Ragdoll's "Pose from clip" row mixes a floating checkbox, a label and a slider knob with no track.
R08Property grids align.One fixed label column per inspector; every field starts at the same x. A long label shortens (full name in a tooltip) instead of pushing its field.Seen: "Default Linear Damping" and "Default Angular Damping" push their fields right of the rest.

Structure

R09Flush columns, cards for groups, no nesting.Columns meet at a 1px divider. Inside a detail panel, related fields group into a card. A card never holds a card, and list rows are never individually boxed unless each row is a rich object (a layer with its animations).
R10Only the content grows.A list body, viewport, timeline or inspector scroll area takes the spare space. Headers, dropdowns, buttons and fields stay at their token height.Seen: Ragdoll's body picker dropdown stretches into a 400px grey box above a crushed list.
R11Navigation and modes look different.The tab list is for moving between tabs. A mode inside a pane is a segmented control in that pane's header, sized to its content. They never share a class.Seen: Flipbooks | Images reuse clip-editor__tab, so they look like a second, misaligned tab strip.
R12One primary action per tab.Light neutral fill, top right of the asset bar or the working pane. Everything else is secondary (outline) or ghost. Icon plus word for primary and secondary; icon only, with a tooltip, in rails and toolbars.
R13Empty is designed.An empty list, detail or viewport shows a title, one line of why, and the action that fills it, centred in the space. Never a blank box.
R14Status lives in the footer.One line in the column's status row, led by a tone dot. Not a floating label between controls.

Colour and state

R15Neutrals come from the editor theme.Surfaces, borders, fields and text use --unity-colors-* variables, so the toolkit follows Unity's dark and light skins. No hard-coded grey in the stylesheet.Seen: rgb(32, 32, 32) tab borders and other literal greys throughout.
R16Blue means selected or focused.Unity's highlight blue marks the selection and a 1px focus border. Status hues mean status. Event and lane colours stay in data.
R17States are visible.Hover lightens by 4–6%; disabled is 40% opacity with no hover; a toggle that is on is filled, not only tinted. Enabled and disabled must never look alike.Seen: Ragdoll's disabled Delete reads almost like the enabled Add.
R18Readable contrast.Body text at least 4.5:1 on its surface; muted text at least 3:1. The theme text on the window background is 7.7:1.

Viewports and proof

R19No magenta.A preview object whose material fails falls back to a neutral grey outline. Magenta is Unity reporting a broken shader, and a buyer reads it as a broken product.Seen: Ragdoll bodies and VAT-mesh proxy quads render solid magenta.
R20One rail style.Viewport tools stack top-left in one 24px icon column on a translucent surface card, 4px apart, the same on every viewport.
R21Icons match their neighbours.16px glyphs in 24px buttons, one stroke weight, drawn glyphs where Unity has none. No mixed built-in sizes in one run.
R22Every visual change ships with captures.Before and after of each affected tab in the docked window at its real size, audited against R01–R21 in the spec's log. A change without a capture is not done.
