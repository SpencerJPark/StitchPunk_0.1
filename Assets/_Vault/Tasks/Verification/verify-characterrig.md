## Goal

Confirm the CharacterRig refactor works end-to-end in `Assets/Scenes/TestArea/DOTSTestScene.unity`. All code is committed, but this is a **full replacement** of four per-part systems — the old authorings (`DesignAuthoring`, `Ragdoll2DAuthoring`, `AnimatorAuthoring`, `AnimationTargetAuthoring`, `AnimationTargetNoIndexAuthoring`) and the `AnimatorTarget` / `AnimationTargetTag` components are **gone**. Every character prefab and every subscene unit therefore has missing MonoBehaviours and **will not bake or animate until re-authored** with the new components. Nothing runs until the Editor migration below is done.

Spec: [`CharacterRig_System.md`](CharacterRig_System.md).

## Steps

### Compile + import (do this first)
- [ ] Re-enter the Unity Editor so scripts compile. Confirm **no compile errors / Burst (BC####) warnings** in the Console (`Unity_GetConsoleLogs` logTypes Error). The MCP compile gate was not reachable when the code was written — this is the first real compile.
- [ ] Confirm **no duplicate-GUID warnings** — the P1 `.cs.meta` GUIDs were hand-generated; the P2 metas were auto-generated by the live Editor. If Unity reports a collision, delete the offending `.meta` and let Unity regenerate it, then re-commit.
- [ ] Systems window → `PartLibraryBakingSystem` and `CharacterRigBakingSystem` are in `PostBakingSystemGroup` (CharacterRig after PartLibrary); `BodyPartInitSystem` is in `SpawnInitSystemGroup` (before `DesignRandomizeSystem` → `MinionRestoreApplySystem` → `DesignApplySystem`).

### Author the PartLibrary (P1 gate)
- [ ] Create one `PartDefinitionSO` per real part kind (menu: **Units ▸ Part Definition**). Do the **head in ExplicitTable mode** against the *existing* array layout (fill `sliceTable`, length `shapeCount * colorCount`, row-major `[shape*colorCount+color]`), and at least one **limb in StrideFormula mode** (`baseSlice + shape*colorCount + color`).
  - [ ] Set `colorAxis = SkinColor` on head/arms/hands/legs/feet/**eyes** (eyes follow skin so zombify recolours them), `HairColor` on hair/mustache, `None` on fixed parts.
  - [ ] Set ragdoll `zones` + `defaultSettleSpeed` on limb joint defs.
- [ ] Create `_PartLibrary.asset` (menu: **Units ▸ Part Library**), add every `PartDefinitionSO`.
- [ ] Add a `PartLibraryAuthoring` GameObject to the scene, assign `_PartLibrary`.
- [ ] Enter Play → Entities window → the library entity has `PartLibrary` with a `PartLibraryBlob` of the expected def count; authored slots have real `shapeCount`/`colorCount`/zones, unauthored slots are safe defaults (shapeCount 1, no zones).

### Migrate a character prefab (P2 gate — do the citizen first)
- [ ] On the **body root**: remove `AnimatorAuthoring` + `Ragdoll2DAuthoring` + `DesignAuthoring`, add **`CharacterRigAuthoring`**. Re-enter the starting animation layers, the ragdoll root config (`visualChild`, fall speed, ground buffers, tilt offsets), and check `reloadDesign` for subscene-placed units.
- [ ] On **every part GO**: remove `AnimationTargetAuthoring` / `AnimationTargetNoIndexAuthoring` **and** `BaseParentAuthoring` (BodyPartAuthoring now bakes `BaseParent` itself — leaving both = a duplicate-component bake error), add **`BodyPartAuthoring`**. Set `target`, `characterRoot`, `partDef` (the matching `PartDefinitionSO`, or leave null for fixed parts), `baseImageIndex`. Tick `isRagdollJoint` on bend pivots (optionally set `settleSpeedOverride`), `isItemSocket` on `ItemLeftHand`/`ItemRightHand`.
- [ ] Rebake (reopen the subscene / re-enter Play). Select a spawned citizen in the Entities Hierarchy:
  - [ ] Root `BodyPart` buffer has one entry per part (correct `target` / `partDef` / `flags`), populated **from frame 2** on runtime-spawned units (via `BodyPartInitSystem`) and at bake on subscene units.
  - [ ] Citizen **idles / walks** — pose fan-out works (animation now reads the `BodyPart` buffer). No collapsed quads on the spawn frame.
  - [ ] Spawn via a `UnitSpawner` and confirm the same (LinkedEntityGroup remap path).

### Semantic design (P3 gate)
- [ ] Spawn ~10 citizens → each has **uniform skin** across head/arms/hands/legs (same `CharacterPalette.skinColor`), varied **between** citizens; shapes vary per part.
- [ ] Select one, enable a `ChangeDesignRequest` in the inspector with `paletteChanges.skin = <zombie column index>` (leave `hair = -1 / NoChange`). Next frame: head/arms/**eyes** flip to zombie variants; hair / fixed parts untouched. `DesignChangeRequest` auto-disables.
- [ ] Save + reload → same look (`PersistedDesign` shapes + `CharacterPalette` round-trip via IPersist). Old save files are invalid by design — delete them first.

### Ragdoll (P4 gate)
- [ ] Kill a unit → body tilts and joints settle into the **blob-authored zones** for their `partDef`; behaviour matches pre-refactor.
- [ ] Put a `settleSpeedOverride` on one joint's `BodyPartAuthoring`, rebake, kill again → that joint visibly settles at the overridden speed (override wins over blob default).
- [ ] Revive the unit → joints + body reset cleanly (Ragdoll2DReviveSystem walks the `BodyPart` buffer).

### Breadth + cleanup (P5 gate)
- [ ] Migrate the remaining character prefabs (rotter, minion, player body) and any subscene units the same way.
- [ ] Build `HumanMaleHead.prefab` (a GO subtree with `BodyPartAuthoring` nodes) and nest it under **two** different `CharacterRigAuthoring` roots → the shared head renders correctly on both and a design roll on each stays independent.
- [ ] Animation Editor: open the preview, confirm it still drives a rig (it now queries `BodyPart`); this pass is compile-fix only, so preview fidelity is best-effort.

## Notes
- The Unity MCP server was **not connected** during the build, so the code passed static review only — treat the first Editor compile as the real gate and expect to fix any Burst-specific issues surfaced there.
- `NeedsAnimatorInit`/`NeedsRigInit` from the plan never existed in code — spawn-init is `NewlySpawned`-driven, so `BodyPartInitSystem` filters on `NewlySpawned` exactly like the old `AnimatorTargetInitSystem`. No spawner change was needed.
- `groundBufferOverride` on `BodyPartAuthoring` is authored but has no runtime consumer yet (the fake-ragdoll sim only uses the root's ground buffer) — kept for forward-compat, matching the old authoring which also exposed it unconsumed.
- Existing prefabs/subscenes will show **"missing MonoBehaviour"** until migrated — that is expected, not a regression.
